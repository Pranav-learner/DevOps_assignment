# Amazon Simple Storage Service (S3) — Scalable Cloud Object Storage

## 1. What is Amazon S3?

**Amazon Simple Storage Service (Amazon S3)** is an industry-leading object storage service offering industry-leading scalability, data availability, security, and performance. S3 stores data as **objects** within **buckets**.

Unlike block storage (EBS) or file storage (EFS), object storage organizes data in a flat namespace with comprehensive metadata tags and unique object keys. S3 provides **99.999999999% (11 9's)** of durability by automatically replicating data across a minimum of three geographically separated Availability Zones within an AWS Region.

```
+-----------------------------------------------------------------------------------------+
|                                Amazon S3 Global Fabric                                  |
|                                                                                         |
|   Bucket: `corp-production-datalake` (Region: us-east-1)                                |
|   ├── Object: `raw/logs/2026-10-07.json.gz`                                             |
|   │   ├── Key: "raw/logs/2026-10-07.json.gz"                                            |
|   │   ├── Value: Raw byte stream (0 bytes to 5 TB)                                      |
|   │   ├── Version ID: `3/L4kqtJlcpXroDTDmJ+rmSpXd3dIbrHY`                               |
|   │   ├── Metadata: `{"Content-Type": "application/gzip", "environment": "production"}`|
|   │   └── Server-Side Encryption: AWS-KMS (`arn:aws:kms:us-east-1:...`)                 |
|   └── Multi-AZ Durability: Stored across AZ-1, AZ-2, and AZ-3 simultaneously            |
+-----------------------------------------------------------------------------------------+
```

## 2. Buckets and Objects

### 2.1 S3 Buckets
- **Globally Unique Namespace**: Bucket names are globally unique across all AWS accounts worldwide.
- **Naming Constraints**: 3 to 63 characters long, lowercase letters, numbers, hyphens only; no uppercase letters or underscores.
- **Region Placement**: Created in a specific AWS Region; data never leaves the chosen region unless explicitly configured via Cross-Region Replication (CRR).

### 2.2 S3 Objects
- **Size Limits**: An individual object can range from 0 bytes up to **5 TB**. Single `PUT` requests support up to 5 GB; objects larger than 100 MB should use **Multipart Upload**.
- **Object Components**:
  - **Key**: The name or prefix path assigned to the object (e.g., `photos/2026/avatar.png`).
  - **Value**: The binary content data.
  - **Version ID**: Unique string generated by S3 when Versioning is enabled.
  - **Metadata**: System metadata (e.g., `Content-Type`, `ETag`, `Last-Modified`) and user-defined custom key-value tags.
  - **Access Control / Tags**: Granular object-level ACLs and resource tags.

## 3. S3 Storage Classes

AWS S3 provides tiered storage classes designed for varying access patterns, retrieval speeds, and cost profiles:

| Storage Class | Designed For | Retrieval Speed | Minimum Duration | Durability |
|---|---|---|---|---|
| **S3 Standard** | Frequently accessed active data | Milliseconds | None | 99.999999999% (3+ AZ) |
| **S3 Intelligent-Tiering** | Unknown or unpredictable access patterns; automatically moves data between 3 tiers | Milliseconds | None (small monitoring fee) | 99.999999999% (3+ AZ) |
| **S3 Standard-IA (Infrequent Access)** | Long-lived, infrequently accessed data requiring rapid access | Milliseconds | 30 days | 99.999999999% (3+ AZ) |
| **S3 One Zone-IA** | Non-critical, reproducible data; lowest cost rapid-access tier | Milliseconds | 30 days | 99.999999999% (**1 AZ only**) |
| **S3 Glacier Instant Retrieval** | Rarely accessed data requiring millisecond retrieval | Milliseconds | 90 days | 99.999999999% (3+ AZ) |
| **S3 Glacier Flexible Retrieval** | Archive data where retrieval in minutes to hours is acceptable | 1-5 min (Expedited) / 3-5 hrs (Standard) | 90 days | 99.999999999% (3+ AZ) |
| **S3 Glacier Deep Archive** | Long-term digital preservation, regulatory compliance | 12 to 48 hours | 180 days | 99.999999999% (3+ AZ) |

## 4. Versioning

**S3 Versioning** maintains multiple variants of an object in the same bucket:
- **Accidental Overwrites & Deletions**: When enabled, deleting an object inserts a **Delete Marker** instead of destroying the file. Retrieving previous versions or removing the delete marker restores the object.
- **Permanent Deletion**: Requires explicitly referencing the specific `VersionId` in the `DeleteObject` API call.
- **MFA Delete**: Requires physical multi-factor authentication codes to change versioning state or permanently delete object versions.

## 5. S3 Lifecycle Management Policies

Lifecycle rules define automated actions to optimize storage costs over time:
- **Transition Actions**: Automatically shift objects to cheaper tiers as they age:
  - Day 0: `S3 Standard`
  - Day 30: Transition to `S3 Standard-IA`
  - Day 90: Transition to `S3 Glacier Flexible Retrieval`
  - Day 365: Transition to `S3 Glacier Deep Archive`
- **Expiration Actions**: Permanently delete objects or noncurrent version variants after a designated retention period (e.g., delete noncurrent versions after 60 days).
- **Multipart Upload Cleanup**: Abort incomplete multipart uploads after 7 days to eliminate hidden storage costs.

## 6. S3 Data Encryption

S3 supports comprehensive encryption at rest and in transit:

### 6.1 Encryption in Transit
- Enforced via HTTPS (TLS 1.2/1.3).
- Can be mandated via Bucket Policy requiring `"aws:SecureTransport": "true"`.

### 6.2 Encryption at Rest
| Encryption Mechanism | Key Management | Description |
|---|---|---|
| **SSE-S3 (Server-Side Encryption with S3 Managed Keys)** | AWS manages keys (AES-256) | Default encryption for all new S3 buckets. Zero configuration, zero additional charge. |
| **SSE-KMS (AWS Key Management Service)** | Customer or AWS managed KMS keys | Audit trails in CloudTrail for every key decryption; customizable key rotation and access policies. S3 Bucket Keys reduce KMS API costs by up to 99%. |
| **SSE-C (Customer-Provided Keys)** | Client manages keys | Client passes encryption key in HTTP header; AWS encrypts/decrypts on write/read and discards the key. |
| **Client-Side Encryption** | Client manages keys | Data encrypted on client machine prior to transmission over network to S3. |

## 7. S3 Bucket Policies & Security

**Bucket Policies** are resource-based JSON access control policies attached directly to S3 buckets.

### Key Policy Use Cases:
1. **Enforce HTTPS Only**: Deny any HTTP requests lacking TLS.
2. **Deny Unencrypted Uploads**: Reject `s3:PutObject` calls that lack `x-amz-server-side-encryption`.
3. **Block Public Access (BPA)**: Account-level and bucket-level master switch that overrides all ACLs and policies granting public access.
4. **Cross-Account Access**: Grant read/write access to specific IAM roles in external partner AWS accounts.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "EnforceTLSRequestsOnly",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:*",
      "Resource": [
        "arn:aws:s3:::production-secure-vault",
        "arn:aws:s3:::production-secure-vault/*"
      ],
      "Condition": {
        "Bool": {
          "aws:SecureTransport": "false"
        }
      }
    }
  ]
}
```

## 8. Common S3 Use Cases

1. **Enterprise Data Lakes**: Centralized repository storing raw structured and unstructured data queried with Amazon Athena, AWS Glue, and Amazon EMR.
2. **Static Website Hosting**: Serving single-page applications (React, Vue) combined with Amazon CloudFront CDN and Route 53.
3. **Backup and Disaster Recovery**: Immutable backups using S3 Object Lock (WORM - Write Once, Read Many) for ransomware mitigation.
4. **Software Artifact & Media Delivery**: Distributing installation packages, streaming video assets, and user uploads.
